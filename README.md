## brainstorming — 对话式需求头脑风暴技能

在任何创造性工作（创建功能、构建组件、添加功能或修改行为）之前，通过自然的协作对话将想法转化为经过验证的设计方案：先探索项目上下文，再逐一提出澄清问题，给出 2-3 种候选方案及权衡分析，分节展示设计并获得确认——确认之前不写任何代码。

### 输出模式

| 你的表述 | 行为 |
|---------|------|
| 未明确要求生成文档（如"给出文本\*\*方案"） | 方案只在对话中展示，**不创建任何文件** |
| 明确要求"生成\*\*文档/方案" | 方案确认后写入文档文件 |

文档分为四类：**实施方案、解决方案、可行性方案、需求文档**，统一存放与命名规则：

- 存放目录：`.doc/<yyyy-MM-dd>/`
- 命名规则：`.doc/<yyyy-MM-dd>/<topic>-<文档分类>.md`

## 示例：.doc/2026-10-24/user-auth-实施方案.md
### 确认即实现
下达确认命令（如"确认无误，开始实施"）后立即开始写代码：有文档则参照文档，无文档则参照对话中确认的方案。不单独产出实现计划文档，不自动 git commit——避免臃肿的中间产物，让对话保持轻量。
